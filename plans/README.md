## Recommended execution order

1. **003** (entrance durations) — pure duration edits on 3 selectors, zero risk of touching anything another plan needs. Do this first to get it out of the way.
2. **002** (bar-fill transform) — isolated to 2 CSS rules + 4 JS call sites, no overlap with any other plan.
3. **004** (gate card hover) — isolated to 1 selector.
4. **005** (tokenize easings) — adds 3 new `:root` tokens and repoints 4 existing call sites. Do this before 006 if you want 006 to reference `var(--ease-icon)` instead of the inline literal (006 works correctly either way — see its Repo Conventions section).
5. **006** (popover entrance) — the largest plan (3 components × CSS + JS). Independent of every other plan; only *optionally* reads a token from 005.
6. **001** (reduced-motion) — do this **last**, after 002/003/004/005/006 have landed, since its `@media (prefers-reduced-motion: reduce)` block redefines several of the same keyframes/selectors those plans touch (`cardIn`, `up`, `panelIn`, `cmpCoachIn`, `.card:hover`). Landing it last means the reduced-motion overrides are written against the final, settled versions of those rules rather than needing a follow-up pass. If 006 has landed by then, also add the two-line `.pop-open{transform:none}` override called out in 001's Boundaries section and 006's Boundaries section.
7. **007** (gallery hero crossfade) — fully independent of everything else; can run at any point, listed last only because it's the lowest-severity/lowest-reach item.

## Dependencies between plans

- **001 ↔ 002**: 001's `@media` block must NOT add a rule for `.feel-bar-fill`/`.perf-bar-fill` regardless of execution order — both plans' Boundaries sections already say this explicitly. No action needed beyond following each plan as written.
- **001 ↔ 006**: if both land, 001's reduced-motion block should also neutralize the new `.pop-open` transform (see step 6 above). If 006 hasn't landed when 001 runs, skip that part — 001 does not depend on 006 to be correct on its own.
- **005 ↔ 006**: purely optional token reuse, no hard dependency in either direction.
- All other plans (002, 003, 004, 007) touch entirely disjoint selectors/functions and can run in any order relative to each other.
